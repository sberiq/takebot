# Самостоятельно размещаемый Telegram-бот предложений

Исходный код: [github.com/sberiq/takebot](https://github.com/sberiq/takebot).

Это открытый конструктор ботов для сбора предложений, модерации и публикации в Telegram-канал. Каждый оператор запускает собственный экземпляр со своим основным ботом, администратором и базой SQLite. Общего бота и общей базы между установками нет; владелец экземпляра может подключать к нему свои дочерние боты.

## Возможности

- Приём текстов, фото, видео, аудио и альбомов через дочерние боты.
- Ручная модерация в выбранном чате и публикация в канал.
- Анонимные и обычные предложения, блокировки, статистика и рассылки.
- Необязательная ИИ-модерация через Gemini.
- Rich HTML, форматирование Telegram и Premium custom emoji.
- Необязательное создание дочернего бота через Bot Management Mode в Telegram.
- SQLite хранится локально внутри отдельной установки.

## Добавление и настройка дочернего бота

1. В личном чате с основным ботом нажмите **➕ Добавить бота**.
2. Чтобы создать бота вручную, откройте @BotFather, отправьте `/newbot`, задайте имя и username, затем вернитесь в конструктор и нажмите **Я создал бота — подключить**. Отправьте выданный токен одним сообщением: конструктор проверит его и удалит сообщение.
3. Если для основного бота включён Bot Management Mode, появится дополнительный вариант создания и подключения напрямую через Telegram, без копирования токена. Этот вариант необязателен.
4. Откройте панель подключённого бота и нажмите **Подключить группу и канал**. Группу модерации добавьте как администратора без дополнительных прав. Каналу выдайте право **публиковать сообщения**. Привязки, сделанные владельцем, сохраняются сразу; неожиданные привязки требуют подтверждения владельца.
5. В панели откройте оформление постов, настройте верхний и нижний фрагменты и подтвердите предпросмотр. Затем при необходимости задайте приветствие и включите ИИ-модерацию.

Владелец дочернего бота может открыть ту же панель командой `/start` у своего бота. Пользователи отправляют предложения ему в личные сообщения. Администратор рассматривает их в группе, а одобренные публикации появляются в выбранном канале.

## Rich HTML

В настройках оформления можно отправить форматированный текст из Telegram или написать HTML вручную. Бот показывает предпросмотр до сохранения. Rich HTML поддерживает заголовки, абзацы, списки и таблицы, цитаты и раскрывающиеся блоки, формулы, ссылки и кнопки, медиа-теги и Premium custom emoji. В сообщениях с фото или видео расширенная Rich HTML подпись публикуется отдельным сообщением сразу после медиа, потому что Telegram не принимает Rich HTML как обычную подпись к медиа.

Используйте обычную альтернативную подпись внутри `<tg-emoji>` — она будет показана, если Telegram отклонит custom emoji для конкретного бота или чата. Полный список тегов и ограничений приведён в [справке Telegram Bot API](https://core.telegram.org/bots/api#rich-html-style).

## Быстрый запуск через Docker Compose

Нужны Docker Engine и Docker Compose plugin.

```sh
git clone https://github.com/sberiq/takebot.git suggestion-bot
cd suggestion-bot
cp .env.example .env
```

Создайте собственного бота через [@BotFather](https://t.me/BotFather), скопируйте его токен и укажите его вместе со своим числовым Telegram ID в `.env`:

```dotenv
MAIN_BOT_TOKEN=токен_вашего_бота
ADMIN_ID=ваш_числовой_telegram_id
```

Основной бот закрыт для остальных пользователей по умолчанию. Подключённые дочерние боты остаются публичными и принимают предложения.

Запустите экземпляр:

```sh
docker compose up -d --build
docker compose logs -f
```

Данные базы сохраняются в именованном Docker volume `bot_data` между перезапусками и обновлениями. `docker compose down` останавливает бота, сохраняя базу. `docker compose down -v` удаляет и базу.

## Запуск без Docker

Требуется Python 3.10 или новее.

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Укажите `MAIN_BOT_TOKEN` и `ADMIN_ID` в `.env`, затем запустите:

```sh
python main.py
```

Для фоновой работы на VPS настройте systemd-службу от отдельного непривилегированного пользователя. Пример `deploy.sh` создаёт службу `autotakes` и устанавливает зависимости на Ubuntu/Debian.

## Настройки

| Переменная | Назначение |
| --- | --- |
| `MAIN_BOT_TOKEN` | Токен основного бота этой установки, созданного владельцем через BotFather. Обязателен. |
| `ADMIN_ID` | Числовой Telegram ID владельца установки. Обязателен. |
| `DATABASE_PATH` | Путь к локальной SQLite базе. По умолчанию `bot_constructor.db`; Compose использует `/data/bot_constructor.db`. |
| `INSTANCE_OWNER_ONLY` | Ограничивает основной бот владельцем из `ADMIN_ID`; включено по умолчанию. Установите `false`, чтобы разрешить работу другим владельцам. |
| `BOT_MANAGEMENT_ENABLED` | Получать обновления о создании управляемых ботов. Включено по умолчанию; `false` отключает этот способ добавления. |
| `BOT_MANAGEMENT_DEFAULT_NAME` | Имя по умолчанию для нового дочернего бота, если включён Bot Management Mode. |
| `GEMINI_MODEL` | Модель Gemini для ИИ-модерации. По умолчанию `gemini-3.8-flash`. |

ИИ-модерация необязательна. Её ключ Gemini задаётся владельцем для нужного дочернего бота через интерфейс основного бота.

Bot Management Mode в @BotFather включает только дополнительный автоматический способ создания. Он не требуется для работы конструктора: владелец может создавать ботов через `/newbot` в @BotFather и подключать их токенами через основной бот.

## Приватность и ключи

У каждой установки отдельный токен основного бота, база и список дочерних ботов. Сообщения и настройки не передаются в другие экземпляры. При включённой ИИ-модерации выбранный контент заявки передаётся Google Gemini для анализа.

По настройке владельца бота токены и ключи сохраняются в локальной SQLite базе как обычный текст. Не публикуйте `.env` и базу данных, ограничьте доступ к файлам и регулярно делайте закрытые резервные копии. Не запускайте несколько polling-процессов с одной базой.

Включённый по умолчанию `INSTANCE_OWNER_ONLY` закрывает основной бот для всех, кроме Telegram ID из `ADMIN_ID`. Так каждая установка обслуживает своего владельца. Если оператор специально хочет открыть основной конструктор другим пользователям, он может задать `INSTANCE_OWNER_ONLY=false`.

## Разработка

Зависимости перечислены в `requirements.txt`. Проверьте синтаксис командой:

```sh
python -m compileall -q main.py main_bot.py database.py sub_bot_manager.py services
```

Баги и предложения можно оформить в Issues upstream-репозитория.
